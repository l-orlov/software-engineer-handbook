# Algorithms: Problems (Easy/Medium)

Не решения целиком — подход + сложность + ловушка, на которую обычно попадаются. Решать самому вслух, проговаривая подход, прежде чем писать код.

## 1. Two Sum
Дан массив, найти два индекса, сумма которых = target.
**Подход**: map `значение → индекс`, один проход: для каждого `x` проверяем, есть ли `target - x` в map, если нет — кладём `x` в map. **O(n) время, O(n) память.**
Ловушка: наивный O(n²) двойной цикл — первое, что говорят, но это не тот ответ, который ждут от Senior.

## 2. Valid Parentheses
Проверить, что скобки `()[]{}` сбалансированы.
**Подход**: stack — на открывающей скобке push, на закрывающей — pop и сравнить с ожидаемой парой; в конце stack должен быть пуст. **O(n)/O(n)**.
Ловушка: забыть проверить пустой stack перед pop (закрывающая скобка без открывающей) и забыть проверить, что stack пуст в конце (лишние открывающие).

## 3. Merge Intervals
Дан список интервалов, объединить пересекающиеся.
**Подход**: отсортировать по началу интервала, пройти один раз, сравнивая конец текущего накопленного интервала с началом следующего. **O(n log n)** (сортировка доминирует).
Ловушка: забыть, что интервалы могут не только пересекаться, но и "касаться" (`[1,3]` и `[3,5]`) — уточнить у интервьюера, считается ли это пересечением.

## 4. Top K Frequent Elements
Найти K самых частых элементов в массиве.
**Подход**: посчитать частоты через map — O(n), затем min-heap размера K по частоте — O(n log k). Альтернатива для целых значений частот — bucket sort по частоте, O(n).
Ловушка: сортировать все элементы по частоте целиком (O(n log n)) вместо heap/bucket — рабочее, но не оптимальное решение; стоит явно сказать про trade-off.

## 5. LRU Cache
Реализовать кэш с вытеснением наименее недавно использованного элемента, get/put за O(1).
**Подход**: `map[key]*Node` + двусвязный список для порядка использования. get — найти узел через map, переместить в голову списка. put — если ключ есть, обновить и переместить в голову; если нет и превышен лимит — удалить хвост списка и его запись из map. **O(1)/O(1)** на операцию.
Ловушка: попытка сделать через `container/list` + map без аккуратной синхронизации указателей узла и записи в map — типичная классическая Senior-задача, к ней стоит подготовиться написать руками.

## 6. Kth Largest Element in an Array
Найти K-й по величине элемент без полной сортировки.
**Подход**: min-heap размера K (как в Top K) — O(n log k). Альтернатива — Quickselect (партиционирование как в quicksort, но рекурсия только в одну сторону) — average O(n), worst O(n²).
Follow-up: «Как гарантировать worst-case O(n) вместо average?» → median-of-medians для выбора pivot (упомянуть, что на практике почти никогда не реализуют вручную — это ответ на теоретический follow-up, не production-код).

## 7. Binary Search (и Search in Rotated Sorted Array)
Классический бинарный поиск + вариант, когда массив отсортирован, но "повёрнут" (rotated).
**Подход** для rotated: на каждом шаге определить, какая из двух половин (`left..mid` или `mid..right`) точно отсортирована (сравнить `arr[left]` и `arr[mid]`), затем проверить, лежит ли target в диапазоне этой отсортированной половины — если да, искать там, иначе — в другой. **O(log n)**.
Ловушка: забыть про дубликаты — если `arr[left] == arr[mid] == arr[right]`, нельзя однозначно определить отсортированную половину, придётся сузить границы на 1 (деградация к O(n) в худшем случае).

## 8. Sliding Window: Longest Substring Without Repeating Characters
Найти длину самой длинной подстроки без повторяющихся символов.
**Подход**: два указателя (окно) + map/set с последней позицией каждого символа. Расширяем правую границу, если встретили повтор внутри окна — схлопываем левую границу до позиции сразу после предыдущего вхождения символа. **O(n)** (каждый указатель проходит массив максимум один раз).
Ловушка: при обнаружении дубликата сдвигать левую границу на 1 в цикле вместо прыжка сразу к нужной позиции — рабочее, но не оптимальное решение (по факту всё равно O(n), но менее чистый код).

## 9. Prefix Sum: Subarray Sum Equals K
Найти количество подмассивов с суммой ровно K.
**Подход**: map `накопленная_сумма → сколько раз встречалась`, идём по массиву, на каждом шаге проверяем, есть ли в map значение `current_sum - K`. **O(n)/O(n)**.
Ловушка: не учесть начальное состояние `map[0] = 1` (пустой префикс с суммой 0) — без этого теряются подмассивы, начинающиеся с индекса 0.

## 10. Two Pointers: Container With Most Water
Найти пару линий, дающих максимальную площадь между ними.
**Подход**: два указателя с разных концов, двигаем внутрь тот, что ниже (площадь ограничена меньшей высотой — двигать больший указатель не может улучшить результат). **O(n)** вместо наивного O(n²) перебора всех пар.
Follow-up: «Почему всегда можно безопасно двигать именно меньший указатель?» — ключевое доказательство корректности жадного подхода, стоит уметь объяснить, а не просто помнить алгоритм.

## 11. BFS: Number of Islands
Посчитать число связных групп "1" в 2D-сетке.
**Подход**: пройти по всем ячейкам, при встрече непосещённой "1" — запустить BFS/DFS, помечая все связанные "1" как посещённые, инкрементировать счётчик. **O(rows × cols)**.
Ловушка: рекурсивный DFS на очень большой сетке может упереться в переполнение стека — на собесе стоит упомянуть BFS или итеративный DFS как более безопасный вариант для продакшна.

## 12. Merge K Sorted Lists
Слить K отсортированных связных списков в один.
**Подход**: min-heap по K "текущим головам" списков — на каждом шаге достаём минимум, продвигаем соответствующий список, кладём его новую голову обратно в heap. **O(n log k)**, где n — суммарное число элементов.
Ловушка: наивный последовательный merge списков попарно — O(nk) вместо O(n log k); стоит явно сравнить оба подхода, если спросят про оптимальность.
